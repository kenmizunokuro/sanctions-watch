# Phase 1 follow-up: 根拠付き一括分類と停止条件

承認済み作業: 8件＋1件の原因調査、残りの一括分類、修正案と根拠をPR #24に追加。本番master変更、削除/無効化、Phase 2は対象外。

原因: 区分35/36はkubun_mapの意図的な空文字である。監査が空文字から「財務省:」を生成したため、存在しないカテゴリを期待していた。原本の区分番号と名称・出典が確認できる場合、表示ラベルの未確定はCATEGORY_LABEL_UNRESOLVED（要レビュー、非ブロック）とし、原本不在や未知のCSV構造等のUNDETERMINED（ブロック）と区別する。区分名は推測で補わない。

旧キー1件は、外側の引用符を取り除く前に姓名順を処理した旧正規化から発生した。現在は同一表示名の正しいキーの行もある。修正案はmetadataを保持する統合案として出力するが実行しない。既存キー全体を再採番すると別の重複/衝突を生むため採用しない。

残りはread-onlyのtriageエンジンで、current原本、保存原本、Alias履歴を分けて突合する。同名別Partyは同一視しない。履歴フラグだけで過去原本を確認済みと主張しない。現在の主名称/別名に由来するカンマ除去等の表記候補、現役Weak、過去Party/別名、非名称欄（呼出符号/船主等）の一致、根拠未確認を分類し、行とURL/hash/位置を出す。照合には文字列一致/既存キーのみ使用しfuzzy推測はしない。

分類済み≠保持承認済み。根拠未確認/非名称混入/キー不整合、未承認の保持問題は公開を止める。保持の承認は、具体的なfindingとmaster行・Party関係・根拠に固定した別ファイルで明示する。コードが初期承認を作ったり、件数baselineや日付だけで免除したりしない。新規の欠落/誤生成/ID不整合/原本破損は免除不可。

成果物: 修正済みauditor、再現可能なtriage CLI、全件根拠付きJSON/CSVと要約、旧キー統合案、明示承認の仕組み（承認実データなし）、追加テスト、更新PR。初回証跡は保存し続ける。
