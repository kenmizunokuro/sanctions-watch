# Phase 1 未確認名称の公式発表追跡

初回要件の原本との関係・根拠URL/hash/該当レコードを補う。保持承認、master変更、削除/解除、Phase 2は行わない。既存の専用ブランチ・PRで続行する。

## Approach

既存の公式発表本文の境界付き一致だけを増やす案は簡単だが、関連先での言及と掲載名の違いを人が追いにくい。過去全リストの再構築は保存原本がなく推測になる。採用するのは、公式発表2件の原本を保存して既存triageへ補助根拠として追加し、別の読取専用補助レポートで見出し・段落/二重改行で区切った全レコード・該当文字位置を示す案。これは実装者の判断であり、ユーザーによる各行の保持承認ではない。

## Boundaries

- OFAC Recent Actions 20260727 / 20251218を既存fetchで通常GET。200の本文、最終URL/hashを保存する。経産省・外務省には接続しない。
- 既存の20250630原本・過去証跡は不変。3ページとも過去の発表で、current=false。
- 名称の完全な語境界付き言及を対応候補とする。見出し・レコード・位置は原文へ戻るための文脈。名前/別名/関連先の役割、Party ID、同一人物、現在掲載、解除、保持可否を推測しない。
- HTML本文領域だけを読む。欠落/重複/未閉鎖領域、異常構造、本文hash/パス異常、無効baselineは明示的に失敗する。未知見出しはそのまま記録して、アクションを分類しない。
- 補助レポートはRESEARCH_ONLYであり、公開ゲートには使わない。既存ゲートは未解決・未承認のままBLOCKEDを維持する。
- 参照するbaselineは10月24日のperson-triageを本文hashで固定。再現はネットワーク不要、既存ファイルの上書き拒否。

## Deliverables

`src/integrity_notice_context.py`、実動作テスト、追加原本/manifest、全件audit/triage・PENDING候補・残対象・文脈レポート、結果資料。通常監査の入力master/state/raw/Alias履歴は変更しない。
