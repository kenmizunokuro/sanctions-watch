# Phase 1 過去公式発表の明示別名欄を照合する監査

2026年10月26日（日本時間）。出典未確認1,486件のうち263件に、保存済み公式発表の明示a.k.a./f.k.a.欄との対応候補が付いた。出典未確認は1,223件となり、従来の本文言及340件と合わせて603件を新分類 `NOTICE_ALIAS_FIELD_REVIEW` にした。この分類は**保持承認の対象外**。原文の別名欄に名称キーの対応があるという意味であり、元masterとの人物同一性、現在掲載、解除、保持意図を確定したものではない。

## 根拠と停止条件

原文のa.k.a./f.k.a.の区別は保存するが、Party IDやWeak品質を推測しない。proofはcurrent=false、source_id=None、weak=None。現在の原本や過去リストで既に確認した強い根拠がある場合は、その分類を優先する。新しい分類から保持承認を適用できないこともテストした。

- d.b.a.やn.k.a.等の未対応マーカー、空欄、不正区切り、閉じない括弧/ASCII・対応する文字組の引用符、孤立した別名宣言を部分採用しない。
- `Linked To:`/`Related To:`の中だけにある別名を、そのレコード自身の別名として採用しない。括弧外の関係ラベルも拒否する。一方、閉じた関係欄が変更前の記載にあっても、後の独立した別名グループを不当に拒否しない。
- 宣言を解析できなければtriage失敗となり、実bashゲートは公開sentinelへ到達せず失敗JSONを保存する。「変更なし」にはしない。
- 同じ別名が複数レコードにある場合も全文と関係を残す。review_idは元レコードhash、マーカー、節見出し等にも固定する。

これは過去発表の記載フィールドを確認する追加根拠である。掲載名・別名・関連先の人物同一性を名前キーだけで結論付けない。基本監査の必須名称集合や承認適用ルールは変更していない。
